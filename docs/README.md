# Anchor Documentation Map

Start with `CURRENT_STATE.md` for live project status.

## Live guidance

- `../AGENTS.md` and `../CLAUDE.md`: agent rules and reading order
- `CURRENT_STATE.md`: accepted baseline, active gate, and next work
- `development/ANCHOR_DEVELOPMENT_PROTOCOL.md`: gate and verification protocol
- `architecture/`: ratified architecture authorities and completed gate records

## Financial and implementation specifications

The root-level financial, golden-case, and detailed-model documents remain
authoritative for the conventions they define. Their implementation-status
headers identify when the corresponding product work merged.

## Historical records

- `plans/`: dated plans and gate records; not live status
- `solutions/`: reusable lessons, including predecessor-era examples; verify
  paths against the current tree

Do not use an old branch name, commit baseline, test count, "not yet
implemented" statement, or "next gate" statement from a historical document
to infer current project state.
